# Envelope Mastering Suite v1.1.1

Envelope Mastering Suite（EMS）は、SunoなどのAI生成音源を主対象とする、ローカル動作の単一HTMLマスタリングアプリです。音源をサーバーへ送信せず、ブラウザ内で解析、5段のDSP、比較試聴、WAV書き出し、バッチ処理まで完結します。

v1.1.1は、v1.1.0で追加した「適応型デノイズ」を含む5段マスタリング構成を維持する修正リリースです。デノイズの段別試聴は他の試聴・再補正開始時に確実に停止し、詳細グラフは非表示状態での描画を避けて表示後に安定して描画します。旧製品 Music Envelope Leveler（MEL）のレベリング技術を中核に、Tonal Envelope Matcher（TEM）由来のトーンEQ、適応型マスタリングコンプレッサー、3帯域リバーブを統合しています。

## 処理チェーン

```text
入力
  → 適応型デノイズ（De-click → Micro-burst Repair → Spectral Denoise）
  → トーンEQ
  → エンベロープ・レベラー
  → マスタリング・コンプレッサー
  → 3帯域リバーブ
  → ピーク／Integrated LUFS参考測定
  → 必要に応じて正規化
  → WAV出力
```

各処理段は独立してON/OFFでき、現在の設定から入力音源を毎回再処理します。前回の処理結果へ重ね掛けはしません。

## 主な機能

- 適応型デノイズ（既定ON／「弱い」）
  - 48 kHz換算16サンプル以下の高Confidenceな微小クリックだけを安全補間
  - 数ms～数十msの短いプチノイズ群を検出し、突出した高周波残差だけを局所抑制
  - 強度プリセットは「弱い」「普通」「強い」「非常に強い」。既定の「弱い」は全曲Spectral処理を行わず、ドラム試料への差分を−60 dB未満に抑えるよう校正
  - 「普通」はドラムを優先保護し最大4.5 dB、「強い」は処理量を増やし最大10 dB、「非常に強い」は低Confidence候補まで最大12 dB処理
  - 目的別に「クリック特化」「傷ノイズ・裾野特化」「持続高域ノイズ特化」を収録
  - クリックをアンカーに前後のレコード傷状ノイズを追跡するBurst Tail Repair（強い: 前後各60 ms、非常に強い: 各120 ms）
  - 確定アンカー周辺だけで直前／直後のスペクトルを参照し、「ジリジリ」した高域の裾野を抑える局所スペクトル修復（非常に強い: 最大10 dB）
  - 検出感度、裾野追跡、局所スペクトル感度／開始周波数／最大量、トランジェント保護、全曲Spectral量を詳細調整し、ユーザープリセットへ保存可能
  - 低Confidence／長い候補は自動修復せず、要確認として記録
  - 曲全体の統計から持続性・平坦性・非調波性を評価し、必要な高域だけを最大3 dB抑制
  - トーナル成分、トランジェント、ステレオ像を保護し、確度不足時は自動BYPASS
  - TEMがノイズリスク帯域を2 dB以上再ブーストする場合に警告（EQカーブは自動変更しない）
- トーンEQ
  - 20 Hz～20 kHzを1/24オクターブ刻みで解析
  - リファレンスモデルへ滑らかに近づける最小位相FIR
  - 局所的な残差を抑えるResidual Correction EQ
  - サブソニック成分を整理するラウドネス効率化EQ
  - 2バンドの手動Bell EQ
  - 複数曲の統計からユーザー・リファレンスモデルを作成
- エンベロープ・レベラー
  - 短期ピーク包絡から時間方向の音量ムラを解析
  - 基準カーブ、変化速度、補正量、最大ブースト／カットを制約した滑らかなゲイン補正
  - 飛び出し抑制と詳細グラフ
- マスタリング・コンプレッサー
  - 平均ゲインリダクション目標から曲ごとに閾値を自動決定
  - ソフトニー、サイドチェインHPF、ピークガード、ルックアヘッド、最大GR制限
  - 入出力LUFSを一致させるメイクアップと推定True Peak天井
  - 「大きくする」のではなく、同じラウドネス内でピークと音の胴体の関係を整える設計
- 3帯域リバーブ
  - Dryを維持し、Low / Mid / HighのWetだけを帯域別に生成
  - Room / Studio / Plate / Hall / Stadium / Churchプロファイル
  - マスタリング用、クリエイティブ用、特殊空間のプリセット
- 比較と運用
  - 処理前A／最終処理後B／Wetのみ／比較Cの共通タイムライン試聴
  - 各詳細タブで処理段直前／直後を比較
  - 設定と処理済み音源を一時保持する比較Cスナップショット
  - 複数ファイルを同じ5段設定で順次処理するバッチ機能
  - バッチ中のLUFS未達、ピーク制限、PCMクリップ等を右ペインへ警告

## 起動

1. `index.html`をChromeまたはEdgeで開きます。
2. 「補正対象ファイル」でWAVまたはMP3を選びます。
3. 各処理段のON/OFFとプリセットを選びます。
4. 「補正処理を実施」を押します。
5. A/B/C試聴と各詳細タブを確認し、必要なら設定を変えて「入力から再処理」します。
6. WAVを書き出します。

ローカルファイルとして動作しますが、ブラウザの制約を避けるには静的HTTPサーバー上での利用も推奨します。

```powershell
py -m http.server 8080 --bind 127.0.0.1
```

Python Launcherが利用できない環境では、任意の静的Webサーバーを同じフォルダで起動してください。通常の単曲処理は、`index.html`を直接開くだけでも利用できます。

## 対応環境と形式

- 主な確認環境: Windows 11 + Google Chrome / Microsoft Edge
- 入力: PCM 8 / 16 / 24 / 32-bit WAV、IEEE Float 32-bit WAV、MP3、ブラウザがデコードできるFLAC
- 出力: 8 / 16 / 24 / 32-bit PCM WAV、32-bit Float WAV
- バッチのフォルダ直接保存: File System Access API対応ブラウザが必要
- WMAなど、ブラウザ標準でデコードできない形式は正式対応外

音源全体と中間バッファをメモリ上に保持します。長時間・高サンプルレート・多チャンネル音源や多数ファイルのバッチでは、十分な空きメモリを確保してください。

### 長尺音源

大きなPCM音源では、メモリ消費を抑えるため、内部プレビューWAVを作らず再生位置からの75秒試聴窓を使います。このモードでは比較Cの保存・再生と各処理段の前後試聴を利用できません。標準フローからバッチを始めると、標準フローの音源・B/C・試聴キャッシュは解放されます。残したいBは、バッチ開始前にWAVとして保存してください。

## 専用ファイル形式

各ファイルは内部的にはJSONですが、開くダイアログで用途を識別できるよう専用拡張子を使用します。

| 用途 | 拡張子 |
|---|---|
| 適応型デノイズ・ユーザープリセット | `.emsdenoise` |
| レベラー・ユーザープリセット | `.emsleveler` |
| トーンEQ補正オプション | `.emstoneeq` |
| コンプレッサー・ユーザープリセット | `.emscompressor` |
| リバーブ・ユーザープリセット | `.emsreverb` |
| トーンEQリファレンスモデル | `.emsreference` |

トーンEQでは「リファレンスモデル」と「補正オプション」を別々に選択します。ユーザープリセットが保存するのは補正オプションだけで、リファレンスモデルは含みません。

## 重要な注意

- 本アプリはマキシマイザー／ブリックウォール・リミッターではありません。
- 適応型デノイズは既定ON／「弱い」です。「弱い」は全曲Spectral処理を行わず、音楽成分をほぼ変えない高確度候補だけを最小限処理します。「強い」「非常に強い」は重症音源で音質変化を許容する設定です。音源分離や長い欠損の復元は行いません。
- Integrated LUFSと推定True Peakはブラウザ実装による参考値です。放送納品等の規格適合判定には認証済みメーターを使用してください。
- コンプレッサーのTrue Peakは4相補間による推定で、ITU-R BS.1770準拠の認証測定ではありません。
- 正規化保存でピークがユーザー指定の正規化保存ピークへ達する場合は、0.3 dB低い内部上限へ制限します。これはインターサンプル・ピークの余裕を作る安全策であり、True Peak保証ではありません。
- 16-bit PCM出力には既定で再現可能なTPDFディザーを適用します。24 / 32-bit PCMと32-bit floatには適用しません。
- WAVメタデータは保持しません。
- 入力音源は直接変更しません。書き出しは新しいWAVです。
